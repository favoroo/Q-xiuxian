# 核心工作流：风格锚定与一致性（生成任何美术素材前必读）

> 目标：让几十上百张生成图保持同一画风。原理 = **固定风格前缀 + 参考图** 双保险，
> 两者都登记在项目风格档案 `assets_raw/style/STYLE.md` 里。

生成前固定三步：

1. 读 `assets_raw/style/STYLE.md`，拿到 `STYLE_PREFIX`（风格前缀短语）和锚图路径。
2. 提示词 = `STYLE_PREFIX + 本次内容描述`。
3. 调脚本时加 `-r <锚图路径>`。

---

## 工作流 1：风格锚定（首次使用 / 换画风时）

STYLE.md 中没有锚图时，先补锚再干活：

1. **和用户确认画风方向**（给 2~3 个具体选项，如"Q版卡通粗描边"vs"暗黑像素风"），
   或让用户丢一张喜欢的图/素材包截图进来。
2. 生成锚图（白底、单主体、最能代表画风的图）：
   ```bash
   .agents/skills/media-gen/scripts/gen_image.sh \
     -p "游戏角色设定图：${STYLE_PREFIX} <代表性主体>全身立绘，白色背景，居中" \
     -o assets_raw/style/anchor
   ```
3. **填写 STYLE.md**：把用户钦定的画风浓缩成一句 `STYLE_PREFIX`
   （建议格式：`<风格名>、<线条特征>、<配色特征>、<光影特征>`），
   登记锚图路径与日期，同时回填「光照方向 / 色板倾向 / 剪影要求」字段。
4. 之后所有生成都带 `-r assets_raw/style/anchor.<ext>` + 前缀（见下方各工作流）。

锚图挑选标准：剪影清晰、颜色对比强、光影简单。不满意就重生成，锚图值得花时间。

## 工作流 2：角色一致性（同一角色的不同表情/动作/立绘/头像）

用该角色的**设定图**当参考图（没有就先生成一张设定图并登记到 STYLE.md）：

```bash
gen_image.sh -p "$STYLE_PREFIX 同一个角色：生气表情特写，白色背景" \
  -r assets_raw/style/char_knight.png --keyout 256 \
  -o assets_raw/images/char_knight_angry
```

实测行为（要知晓）：
- 参考图的**构图母题也会被继承**（实验中苹果的"木塞+叶子"被药水瓶继承为"瓶塞+叶子"）。
  画风延续是想要的，构图继承多数时候也是加分项；
  若不要构图只画风，prompt 里明确写"仅保持参考图的画风，构图按我的描述来"。
- 复杂动作/透视的相似度会下降；重要角色建议一次多生成几张挑选。

## 工作流 3：批量小物件（道具图标 / 技能图标 / 掉落物）

用锚图统一风格，清单化循环生成，全部出透明底：

```bash
for item in "红色治疗药水" "蓝色法力药水" "木质宝箱" "金币袋"; do
  gen_image.sh -p "${STYLE_PREFIX} 游戏道具图标：${item}，单一主体，构图居中饱满" \
    -r assets_raw/style/anchor.<ext> --keyout 256 \
    -o "assets_raw/images/icon_<语义名>"
done
```

- 图标建议 `--keyout 256`（游戏内再缩到 64/128）；立绘用 `--keyout 1024`。
- 文件名用语义化英文（icon_potion_red），不要用哈希；manifest.jsonl 里已有 prompt 对照。
- 批量前先试产 1 张给用户过目，风格 OK 再铺量（省配额也省返工）。
- **图标网格草稿技巧**：一次出多样草稿可用 `--grid 2x2` 让模型画"四个变体一表"，
  切分后挑选，选中的再单图重生成精修。

## 工作流 4：图像编辑（改色 / 加细节 / 去元素 / 换背景）

把**原图**当参考图传入，prompt 写修改指令：

```bash
gen_image.sh -p "把这件装备的披风改成深红色，其余一切保持不变" \
  -r assets_raw/images/char_knight.png -o assets_raw/images/char_knight_red
```

- 适合：局部改动、风格微调。不适合：大改构图（不如重生成）。
- 改完的图可以继续当参考图（链式迭代），但建议链不超过 2~3 跳，细节会漂移。

## 透明底管线（--keyout 内部做了什么）

模型**不支持** alpha 通道（实测要求透明底仍返回 JPEG）。管线：

1. 脚本自动在 prompt 追加"纯品红 #FF00FF 背景、主体不触边、无投影"要求
2. 生成 JPEG（模型有时把品红画成内嵌矩形，脚本会自动定位并裁剪）
3. `keyout.py`：品红度量 `min(R,B)-G` 软抠 + 半透明区去品红溢色 + 腐蚀 1px 去晕边
   + 按内容裁剪 + 可选缩放，输出带 alpha 的 PNG
4. 原始图保留为 `<前缀>.raw.jpg`，抠得不干净可调 `keyout.py` 阈值（lo=30, hi=110）重跑

注意：主体本身含大量品红/粉紫色时品红底会误伤 —— 此时在 prompt 里要求换成
纯绿色 #00FF00 背景，并用 `keyout.py` 手动处理（把度量改成 `min(R,G)-B`）。

## 工作流 5：角色多角度（转身表 / turnaround）

游戏需要同一角色的多个视角。**核心技巧：让模型把多个视角画进同一张图再切分**
——同图内天然同角色、同画风、同光照，一致性远高于分开多次生成。

1. 先按工作流 2 生成角色设定图并登记到 STYLE.md。
2. 生成转身表并自动切分（`--grid 列x行`，配合 `--keyout` 逐格出透明图）：
   ```bash
   gen_image.sh -p "${STYLE_PREFIX} 角色转身表：同一角色的正面、侧面、背面三个视角，
     站姿，等距并排，光照方向一致，细节完全一致" \
     -r assets_raw/style/char_<角色>.png --grid 3x1 --keyout 256 \
     -o assets_raw/images/char_<角色>_turnaround
   # → char_<角色>_turnaround_r1c1/c2/c3.png（正/侧/背）
   ```
3. 需要某角度的单张精修图时，**用整张转身表作参考图**（信息最全），
   prompt 里指定要的角度。
4. 原表自动保留为 `<前缀>.raw.jpg`；分格错位（模型分格不等宽）时手动裁原表重切：
   `split_grid.py <原表> <前缀> <列> <行>`。

游戏向经验：
- **top-down 视角游戏**（本项目）常用 4 方向：`--grid 2x2` 一次出 上/下/左/右；
  斜向多数时候用水平翻转 + 程序动画凑合，**别追求 AI 直出 8 方向**——对齐极难。
- 背面/侧面细节模型会自行脑补，重要特征（背包、披风、发型）必须在 prompt 里
  明写"背面可见 XXX"。
- 多方向只给主角和 Boss 做；杂兵用一个角度 + 水平翻转就够。

## 工作流 6：表情 / 动作差分

同理用"一表多格"保一致，切分后即为独立素材：

```bash
# 表情差分（2x2 网格）
gen_image.sh -p "${STYLE_PREFIX} 同一角色表情差分表：普通、开心、生气、受伤，
  2x2 网格排布，头部特写，背景一致" -r assets_raw/style/char_<角色>.png \
  --grid 2x2 --keyout 256 -o assets_raw/images/char_<角色>_expressions

# 动作/姿态差分（如 待机/攻击/受击/死亡，配合程序动画使用）
gen_image.sh -p "${STYLE_PREFIX} 同一角色动作表：待机、攻击、受击、死亡，
  2x2 网格排布，全身，角度与比例一致" -r assets_raw/style/char_<角色>.png \
  --grid 2x2 -o assets_raw/images/char_<角色>_actions
```

- 差分图是**逐帧动画的替代品**：模型生成不了多帧一致的连续动画（能力边界见
  usage-guide.md），游戏里用"差分单图 + 程序动画（位移/缩放/闪白/旋转）"合成动效。
- 格子数越多单格质量越低，2x2 是质量与效率的甜点；需要更多差分就分多次生成。
