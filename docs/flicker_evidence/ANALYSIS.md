日期：2026-10-21

## 一、结论摘要

**这不是 HUD 逻辑/可见性/透明度问题，也不是辉光/HDR 问题，而是 Godot 4.7 Mobile(Vulkan) 渲染器的
2D 批处理在 GPU 端「某一批 draw 命令没有落到屏幕上」——CPU 侧全部正常，GDScript 观测不到。**

## 二、逐帧定位

56 帧中**只有 f032 一帧异常**（P 帧，非关键帧，排除编码伪影）。f031 与 f033 完全正常。

差分三带（顶栏 y0-110 / 中部世界 y200-660 / 底部技能 y700-864）：
f032 顶栏 diff≈21（基线≈1.5），中部世界 diff≈5（基线≈4~5，仅正常运动）。

## 四、排除项（实测/事实，非推测）

- ❌ **辉光/HDR**：f031 里剑光亮度剖面 145→83→32，**完全没有辉光外溢晕**，说明该局 glow 关闭；
  HDR 在移动端自 v0.0.57 起恒为 false（`Main._apply_glow_channel`）。关着还闪 ⇒ 与 glow/HDR 无关。
- ❌ **可见性/透明度**：探针 v4 记录 20853 帧，`hud_vis` 全程 true，GameHUD.visible 全程 true。
- ❌ **绘制量骤降**：探针 `prims` min=8921 / median=15532 / max=22278，**无任何骤降**（若整批没提交，prims 会掉）。
- ❌ **StageBackdrop 黑幕**：战斗中只亮 13 帧，全在开局转场。
- ❌ **2D 灯光照 HUD**：实渲染 A/B，开灯/关灯 HUD 像素相同。
- ❌ **字体缺字**：全量扫源码字符串，缺字 0。

## 五、根因定位（引擎源码交叉验证）

「prims 正常但 UI 部分不显示」= **draw 命令提交了，GPU 端某个 batch 没画出来**。
Godot 4.7 RD 渲染器的 2D 批处理在 `renderer_canvas_render_rd.cpp::_render_batch_items` 里按
`tex_info / clip / material / lighting` 切 batch，每个 batch 用 `instance_buffer` + `uniform_set` 绘制。

**上游已确认的同类缺陷**：godotengine/godot **#112121**「Regression with rendering UI」
- 现象：canvas layer 下的 **stylebox / label 不渲染**
- 明确「**与 batching 相关**」「**影响 Android**」
- 根因：`template_instance.color_texture_pixel_size` 被前一个 batch 的纹理参数污染后串到后续 rect/ninepatch/polygon
- 修复：PR #112131（2025-10-29 合入 master）

本地 4.7.2.stable 已含 #112131 修复（`new_instance_data(*r_current_batch, ...)`），
说明本项目遇到的是**同一批处理代码路径里的另一个未修复变体**（`texture_info_map` 裸指针 / instance buffer 复用 /
uniform_set LRU 淘汰 三者之一）。4.7.2 是当前最新稳定版，无更高版本可升级。

## 六、为什么只有手机、时有时无

- 仅 Vulkan/D3D12/Metal 的 RD 批处理路径有此问题；桌面 Forward+ 的绘制量/纹理状态组合不同，触发不到。
- 是否触发取决于**当帧的 UI 内容组合**（哪些文字宽度、哪些纹理状态、batch 如何切分），
  所以「时有时无、次数不固定、有的局不闪」。
- 与手机 GPU 驱动的 buffer/UMA 行为相关（移动端 UMA 复用 instance buffer）。
